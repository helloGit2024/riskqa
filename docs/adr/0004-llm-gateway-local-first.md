# ADR-0004：LLM 统一网关 + 本地优先，数据不出内网

> 状态：已接受（2026-11-01）｜ 影响面：architecture §二/§4、constraints §四合规、AGENTS P-02

## 一、背景

LLM 在三处被使用：慢路 SQL 生成、意图抽取（签名）、评审材料生成。约束：信贷数据不得出内网（合规硬约束）；同时希望保留云端模型的可能性（叙事类非敏感内容）。V2 已有 ModelRouter/FakeLLM/DegradedLLM 抽象。

## 二、备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 直连云端 API（OpenAI/Anthropic） | 省本地部署 | **数据出境 = 合规红线，一票否决** |
| B. 全本地，无网关抽象 | 最稳 | 模型升级/切换要改调用点；无法按场景分级 |
| C. 统一网关 + 本地优先（本决策） | 数据默认不出内网；provider 可切换；降级链现成 | 多一层（约 200 行） |
| D. 混合路由（敏感走本地、叙事走云端） | 成本/质量平衡 | 分类边界本身是风险点（分错=出境） |

## 三、决策

选择 **C**：所有 LLM 调用经 `llm/gateway.py`（OpenAI 兼容协议）；默认路由本地模型（Ollama/vLLM）；云端 provider 默认关闭，开启需 ADR + 合规审批；不采用 D 的自动分级（边界不可靠，宁可全本地）。

## 四、理由

V2 的 ModelRouter + DegradedLLM 已实现路由与降级；本地模型对"SQL 生成/意图抽取/材料生成"三个任务在 2026 年的能力已够用（有 FakeLLM 基线可对比验收）；网关一层让"换模型"不碰业务代码。

## 五、代价（必填）

- 本地模型质量低于前沿云端（慢路一次通过率预计 60—75%，靠 ≤2 轮修正兜底）。
- 需运维提供一个内网 endpoint（assumptions A-01，未验证）。
- 网关成为单点——降级链（DegradedLLM：能拒答不编造）是必须的，不是可选的。

## 六、复核条件

① 公司获批合规云端通道（专线/脱敏）；② 本地模型三个任务验收不达标（黄金集中 LLM 相关题通过率 <80%）；③ 成本压力显现（本地 GPU 运维贵过云端合规通道）。

## 七、不懂技术的人只需确认哪一点

**"AI 用的模型跑在公司自己的机器上，客户数据不出内网；哪天要用外部模型，必须先批再改"**——是否符合公司合规要求。
