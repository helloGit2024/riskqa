# 架构设计（architecture.md）

> 上游：`constraints.md` + `spec.md`。本文与 `AGENTS.md` 第二节的技术栈表述必须一致。

## 一、系统边界

**管**：风控指标问数（快慢双路）、模型报告生成、监控归因、策略回测的编排与数字生产；语义层与治理配置的加载与校验；运营数据（raw log/事实/评审/晋升/审计）的持久化；REST API 与 MCP 两种对外出口。

**不管**（边界即 spec §四"本期不做"）：自研前端、多租户、直连生产库写入、归因/回测 SQL 沉淀、K8s。

**外部交界**：
- 上游：指标宽表快照文件（CSV/Parquet，数仓 T+1 导出，内网文件服务器）；本地 LLM 服务（内网 endpoint）。
- 下游：Trae / Chat2DB / CLI（经 MCP 或 API）；企微/飞书 webhook（V4.2 起，告警）；审计员（经 get_evidence）。
- **红线**：任何环节不向外网发送指标数据（P-02）。

## 二、技术栈（硬约束，不得擅自更换）

| 层 | 选型 | 版本 | 为什么不选别的 |
|---|---|---|---|
| 语言 | Python | 3.13（开发机实测 3.13.12） | 现有四份代码均为 3.13；dataclass/TypedDict 特性依赖 |
| 数据处理 | pandas + numpy | pandas 2.x / numpy 2.x（requirements 锁小版本） | 现有计算层全部基于它；单机百万行足够 |
| 配置 | PyYAML | 6.x | 语义层/治理配置的人类可读格式；与 V2/V3 实测一致 |
| 编排 | LangGraph | 1.2.x（V2 实测 1.2.16） | 慢路固定图 + interrupt 人审 + checkpoint；迁移到 deepagents 见 ADR-0002 |
| LLM 接入 | 自研网关（OpenAI 兼容协议） | — | provider 可切换、本地优先、降级链；不引 SDK 锁定（ADR-0004） |
| 存储（运营） | SQLite | 3.x（Python 内置 sqlite3） | 零运维、备份=拷文件；无并发写需求（ADR-0003） |
| 存储（指标） | 文件快照 CSV/Parquet | — | manifest 血缘已实现；正式交付永远基于快照（ADR-0006） |
| API | FastAPI | 0.11x | 异步 + 自动校验；内网单服务 |
| MCP | 官方 Python SDK（mcp） | 1.x | 5 工具 stdio+SSE 双通道（ADR-0005） |
| 测试 | pytest + FakeLLM | 8.x | 失败场景可复现、零 token（P-17） |
| 部署 | 内网单机（systemd 或 nohup） | — | 不上 K8s（constraints §五） |

> 版本号来自开发机实测（扫描于 2026-11-01）；上线前以 `requirements.txt` 锁定行为准。

## 三、架构总览（五层四横切）

```
┌─────────────────────────────────────────────────────────────┐
│ 外壳层（可插拔）  Trae · Chat2DB · CLI · API 客户端              │
│                      ↓ MCP / REST（身份随调用传入）              │
├─────────────────────────────────────────────────────────────┤
│ 编排层  ┌─ 快路：alias 归一 → enum 收窄 → 前闸 → 计算 → FactStore │
│         └─ 慢路：LangGraph 固定图 → 交叉验证 → 人审队列          │
├─────────────────────────────────────────────────────────────┤
│ 引擎层  语义层(M1) · 数据层(M2) · 计算层(M3) · 事实层(M4)        │
│         工具层(M5 前后闸) · 校验层(M6 三重闸)                    │
├─────────────────────────────────────────────────────────────┤
│ 治理层  签名归并 · 热度三维 · 口径指纹 · 评审材料 · 晋升 · 升级链  │
├─────────────────────────────────────────────────────────────┤
│ 基础设施  SQLite 六表 · 快照文件 · LLM 网关 · 审计 Observer      │
└─────────────────────────────────────────────────────────────┘
四横切：身份与行级权限（随调用穿透全层）· 审计（Observer 全链路）·
        AI 显著标识（所有出口）· 降级链（LLM 故障 → DegradedLLM）
```

**分层纪律**（架构的一号法则，见 P-03）：LLM 只进入编排层的"意图翻译/路由决策"与叙事层；引擎层 M1—M6 是纯 Python，LLM 禁入。

## 四、核心链路

### 4.1 快路问数（命中语义层）

```
提问 → alias 索引归一(FPD30/首期逾期 → fpd30_rate)
→ 命中？ ┌ 是 → FC 参数 enum 收窄(metric/dims/filters/time_range)
→ 前闸(P-04/08/09：已登记/已签字/维度允许/纯函数已注册)
→ compute_metric 纯函数计算 → FactStore.put → fid
→ 返回：数值 + fact_id + 口径(desc/owner/signed_at) + 证据引用
→ 免审，落审计
└ 否 → 慢路（4.2）
```
失败点与处理：alias 未命中 → 慢路；前闸拒 → 返回拒绝原因（不进 FactStore）；纯函数未注册 → 拒服（P-09，V3 实测场景六）。

### 4.2 慢路探查（未命中/新签名）

```
问题 → 意图解析(LLM) → schema 链接 → SQL 生成(LLM)
→ check_sql 三闸(白名单/LIMIT/行级权限注入 P-10)
→ 执行(沙箱只读) → 失败修正(≤2 轮) → 交叉验证(与快路/重算比对)
→ 结果进 FactStore + raw log 无条件落库(P-12)
→ 人审分级：免审/抽检/必审 → 确认后才可被引用
```
失败点与处理：SQL 注入特征 → 三闸拒；执行超时 → 60s 熔断；交叉验证不一致 → 返回两侧数字+差异说明（V2 实战：抓出 0.224 vs 0.146 口径错误）。

### 4.3 持续运营（V4.2 主链路）

```
raw log → 意图抽取(SQL 锚点) → 签名归并(代码) → 热度三维度
→ 口径指纹(两级：签名内 + 跨签名) → 提名/拦截
→ 评审材料(按签名分组、只标异类) → Owner 签字
→ 晋升三件套(YAML + evidence 快照 + alias 回填 + 纯函数注册)
→ alias 回填 → 快路命中率上升 → LLM 调用减少
```

### 4.4 报告生成（V4.3）

```
spec YAML(固定 DAG) → renderer 注册表逐 sheet 渲染 → FactStore 供数
→ 叙事层(LLM 只写叙事，引用 {{fid}}) → 三重校验闸(P-06/07 + 独立重算)
→ 不过 → 整份回退规则模板 → 过 → 交付(带 data_as_of + AI 显著标识 P-16)
```

### 4.5 监控归因（V4.3）

```
定时任务(规则检测，确定) → 超阈值 → 告警(IM) + 归因下钻(维度假设探索)
→ 结论状态永远"待人工确认"(P-11) → 归因记录进审计
```

## 五、数据流与存储

| 数据 | 形态 | 存哪 | 保留 |
|---|---|---|---|
| 指标宽表快照 | CSV/Parquet + manifest(sha256/data_as_of) | `data/snapshots/` | 12 个月滚动 |
| 语义层 / 治理配置 | YAML | `config/`（Git） | 永久，changelog 留痕 |
| raw log | SQLite `query_log` | `data/ops.db` | **1 年（合规硬约束）** |
| fact / 评审 / 晋升 / 审计 / 告警 | SQLite 五表 | `data/ops.db` | 见 data-model.md |

**写入方**：只有引擎写 SQLite；外壳一律经 API/MCP（P-xx 目录约定）。**备份**：`data/` 目录整拷 + `config/` Git。

## 七、质量瓶颈与简化空间

1. **最大瓶颈是 Owner 产能，不是技术**（V3 §10）：队列积压是机制死亡首因——架构上把"材料生成质量"当一等公民（评审材料是 LLM 生成物里唯一直接给人看的）。
2. **简化空间**：SQLite 单文件（不上 PG）；本地模型一个就够（不上模型集群）；报告渲染同步执行（不上队列）。
3. **预留升级点**（触发条件写进 ADR 复核条件）：并发写 → PG（ADR-0003）；检索增强 → pgvector（ADR-0001 复核）；多主题域 → 语义层分文件。
