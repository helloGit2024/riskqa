# 术语表（glossary.md）

> 目的：防止 AI 一词多义。**同一个词，你和 AI 理解不一样，是很多"莫名其妙改错"的根源。**

## 一、核心术语（用大白话解释）

| 术语 | 在这个项目里指什么 | 不指什么 |
|---|---|---|
| 语义层 | `config/semantic_view.yaml` 定义的指标口径合同：synonyms/dimensions/metrics/tables/tests，Owner 签字生效 | 不是数据库 schema，不是 FC schema |
| 指标卡 | 语义层里每个指标的条目：desc/unit/dims/calc/owner/signed_at/changelog | 不是 BI 卡片 |
| 口径 | 一个指标"怎么算"的完整定义：分子、分母、过滤条件、时间窗 | 不只是指标名或公式 |
| fact_id | FactStore 里每个数字的唯一编号（F0001 起），叙事层唯一合法的数字来源 | 不是数据库主键 |
| FactStore | 全文数字的唯一仓库：put/get/digest，模型只许引用不许直读 | 不是缓存 |
| 快路 | 命中语义层（含 alias）的问数路径：enum 收窄 + 纯函数计算 | 不是"更快的查询"，是"已评审口径的查询" |
| 慢路 | 未命中语义层的探查路径：固定图 + 强制人审 | 不是临时表/缓存通道 |
| 意图签名 | `(metric, dims, filters, time_range)` 四元组，归并的锚点；filters 只记字段不记值 | 不是问题文本、不是 SQL 原文 |
| 口径指纹 | 聚合表达式 + WHERE（字面值归一化后）的哈希，用于检测同指标多口径 | 不是 SQL 全文哈希 |
| 热度 | 签名集群的统计画像：独立用户数/时间分布/集中度（三维度防失真） | 不是查询次数排行，不是质量分 |
| 提名 | 热度达标后自动进评审队列的动作 | 不是晋升，不是"已验证" |
| 晋升 | Owner 签字后：写 YAML + evidence 快照 + alias 回填（+ 注册纯函数） | 不是复制粘贴、不是自动生效 |
| evidence 快照 | 晋升时自包含固化的证据（问法/SQL/签字/评审号），raw log 删了仍可审计 | 不是日志引用 |
| 答案确认 | 分析师点"结果正确"，只累加热度 | 不是口径签字，不定晋升 |
| 口径签字 | Owner 对口径的裁决，唯一能触发晋升的动作 | 不是普通审批 |
| 三级人审 | 免审 / 抽检 / 必审，按场景与敏感度分流 | 不是"审批流"（无前端审批流） |
| raw log | 每次慢路执行的不可变记录（qid/question/sql/sql_edited/result_digest/user/ts/confirmed_by） | 不是全量结果存储 |
| 保留期 | raw log 1 年（合规硬约束）；热度窗口 30 天必须 < 保留期 | 不是永久保存 |
| FakeLLM | 按脚本返回动作的测试替身，失败场景可复现、零成本 | 不是 mock 服务器、不是真模型降级 |
| DegradedLLM | LLM 故障时的规则降级链（能拒答不编造） | 不是备用模型 |
| 黄金题集 | 冻结的评估题库（evals/golden_set.yaml），比结果集不比 SQL | 不是单元测试、不是演示脚本 |
| 归一压缩比 | raw 查询数 ÷ 唯一签名数，意图抽取质量指标 | 不是查重率 |
| 误晋升率 | 事后审计发现口径错误的已晋升指标占比 | 不是回退率 |
| Owner | 主题域指标口径的责任人，唯一有签字权的人 | 不是管理员、不是开发者 |
| 治理组 | 月度抽查晋升质量的组织角色 | 不是审批者 |

## 二、工程术语（本项目专用含义）

| 术语 | 指什么 |
|---|---|
| 外壳 | 引擎外的交互层：Trae / Chat2DB / CLI / API 客户端。可插拔 |
| 引擎 | `src/riskqa/`：语义层+计算+校验+治理的合称。不可外包 |
| 前后闸 | 工具调用前的硬阻断（pre_tool_gate）与执行后的输出检查 |
| 三重校验闸 | 检查 1 裸数字 / 检查 2 编造引用 / 检查 3 Python 独立重算 |
| 独立重算 | 与主流水线分开实现的复算入口，"不相信自己" |
| 行级权限注入 | 执行前把用户可见范围改写成 SQL WHERE（`inject_row_filter`） |
| 枚举收窄 | FC 工具的 metric/dims 参数 enum 从语义层自动生成 |
| 渲染器注册表 | spec 的 module → renderer 函数映射，未注册直接抛错 |
| 升级链 | pending → reminded(72h) → overdue(144h) → shelved(504h) |
| 搁置（shelved） | 组织上没人管，进月度复盘清单；≠ rejected（Owner 看过说不行） |
| D0–D4 | 数据流分层：原始→清洗→schema→语义层→消费 |
| M1–M8 | 工程模块：语义层/数据层/计算层/事实层/工具层/校验层/编排层/测试层 |

## 三、明确不做的术语（出现即跑偏）

| 词 | 为什么禁用 |
|---|---|
| "自主学习" | 本机制是持续运营（continuous curation），90% 是人工评审；叫自学会让管理层期待全自动 |
| "万能问数 Agent" | 四场景确定性光谱不同，焊一个 prompt 四处漏风 |
| "快路缓存" | 快路不是缓存，是已评审口径；未晋升查询没有快路 |
| "AI 算出来" | AI 不算数，只翻译意图和写叙事 |
| "临时指标" | 不存在未评审口径在流通 |

## 四、易混淆对照（高频错误来源）

| 对 | 区别一句话 |
|---|---|
| DB schema vs FC schema vs 语义层 | DDL 约束"数据能答什么"；JSON Schema 约束"模型能提什么参数"；语义层是两者之间的翻译层。DB schema 在语义层**之下** |
| 热度 vs 正确性 | 热度回答"多少人在问"；签字回答"算得对不对"。混为一个信号 = 错误被多数投票放大 |
| 答案确认 vs 口径签字 | 两个动作、两类人、两张表 |
| shelved vs rejected | 没人看过 vs 看过说不行（带理由，防重复提名） |
| 提名 vs 晋升 | 热度只决定优先级，签字才决定晋升 |
| 口径冲突 vs 维度差异 | 分母/过滤/聚合不同才是冲突；GROUP BY 维度不同是同一指标的不同切法 |
| 快路命中率 vs 准确率 | 命中率是运营成效总指标；准确率由黄金集度量 |
| evidence 快照 vs raw log | 快照自包含可审计；raw log 是不可变原始记录 |
| 迁入（V4.0） vs 重写 | 迁入 = 搬运+拆包不改逻辑；重写 = 禁止（行为等价回归兜底） |
