# 版本规划（releases.md）

> **本文件是"版本范围"的唯一来源**，也是 `.trae/rules/project_rules.md` 第 5 节引用的对象。
> 每个版本三块：✅ 做什么 / ❌ 明确不做什么 / ✓ 退出门禁。

## 一、版本总览

| 版本 | 目标 | 周期 | 退出条件（一句话） |
|---|---|---|---|
| V4.0 底座重构 | 四个单文件 → 生产工程结构，运营数据可持久化 | 4 周 | V2/V3 行为等价回归全绿 + SQLite 落库 + pytest 迁移完成 |
| V4.1 问数闭环 | 快慢双路 + 三级人审 + REST API，分析师可用 | 4 周 | 黄金集 ≥95% + 8 类失败场景 PASS + 越权 0 通过 |
| V4.2 持续运营 + MCP 化 | 治理全家桶上线，引擎成为可调用基础设施 | 4 周 | 签名/热度/指纹/晋升/升级链全链路断言 + MCP 5 工具联调 + 误晋升率 0 |
| V4.3 全场景 + 运维 | 报告/监控归因/回测三场景 + 评测扩容 + 运维体系 | 4—6 周 | 四场景验收全过 + 归因收敛率有基线 + 运维手册告警全覆盖 |

> 与原规划差异：早期路线图（落地方案 §09，6—8 周）是"学习+实践双轨"视角；本表是同一路线在工程规范下的展开——底座先行不变，场景按确定性从高到低接入不变，新增的是工程化地基（V4.0）与 MCP 化（V4.2）两个此前未单列的版本。

## 二、V4.0 底座重构

**✅ 做什么**
- `src/riskqa/` 包化：semantic / data / calc / facts / tools / verify / orchestration / governance / llm / store 十个模块，从 V1/V2/V3 四个单文件迁入（行为保持等价，迁移 = 搬运 + 拆包，不改逻辑）。
- 语义层与治理配置外置：`config/semantic_view.yaml` + `config/governance.yaml`（Git 同库同权；代码禁止内嵌默认值，见 P-15）。
- SQLite 持久化：`store/` 模块实现 query_log / fact / review_record / promotion / audit_entry / alert 六表（data-model.md）。
- 测试从 `main()` 断言迁出为 `tests/` pytest 套件：V2 的 9 场景 + V3 的 8 场景全量转为 pytest，FakeLLM 脚本机制保留。
- Makefile + CI 编排（quality-gates.md 的 QG-01/02/03 先行）。
- 现有四个 .py 文件移入 `legacy/` 存档（只读参照，不删除）。

**❌ 不做什么**：不接真 LLM（FakeLLM/规则抽取器）；不做 API/MCP；不加新指标（迁入即当前 5 个）；不改任何计算逻辑；**不做前端**。

**✓ 退出门禁**：① `make test` 全绿且覆盖 V2/V3 全部 17 个场景；② V2/V3 迁入前后输出逐场景比对一致（golden 输出留档）；③ YAML 外置后 `make semantic-check` 通过（5 指标卡三字段齐全）；④ SQLite 六表建成，raw log 落库→读出往返一致。

## 三、V4.1 问数闭环

**✅ 做什么**
- 快路：FC 工具 `ask_metric`（enum 从语义层生成，P-08）+ 同义词/alias 索引 + 前闸（未登记/未签字/维度不允许/无事实禁出报告）。
- 慢路：LangGraph 固定图（schema 链接 → SQL 生成 → 执行 → 修正）+ `check_sql` 三闸（白名单/LIMIT/行级权限注入）+ 交叉验证。
- 校验闸三重检查 + 规则模板回退（M6 迁入 + 中间件化）。
- 三级人审状态机（免审/抽检/必审）+ 评审队列持久化。
- REST API v1：8 端点（api-contract.md），认证用内网 Token + 角色。
- LLM 网关落地：provider 可切换，默认本地模型；ModelRouter/DegradedLLM 保留降级链。

**❌ 不做什么**：不做 MCP（V4.2）；不接 IM 告警（V4.2）；不做归因/回测场景（V4.3）；不扩指标（仍 5 个）。

**✓ 退出门禁**：① `make eval` 黄金集 ≥95%（初始 20 题）；② 8 类失败场景 FakeLLM 测试全 PASS；③ 越权测试 0 通过（行级权限注入生效）；④ 快路 P95 < 2s（1000 次采样）；⑤ API 契约冻结（openapi.yaml 无 ⚙️）。

## 四、V4.2 持续运营 + MCP 化

**✅ 做什么**
- 治理全家盏：意图抽取器（生产版 = LLM 网关调用，接口不变）、签名归并、热度三维度、口径指纹（两级检测）、评审材料生成、晋升三件事、升级链（SLA 72h → 2× → 7×）。
- 治理配置三层 + 护栏（window ≤ retention 等四条）落库生效。
- evidence 快照固化（1 年保留期派生设计）+ alias 回填 + 纯函数同步注册硬纪律。
- MCP Server：5 工具（ask_metric / explore / submit_review / get_evidence / list_governance），stdio + SSE 双通道。
- 外壳联调：Trae（分析师自用）+ Chat2DB（数据团队）；IM 告警通道（企微/飞书 webhook，借 nanobot 模式）。

**❌ 不做什么**：不引入 deepagents 做生产运行时（仅 V4.3 归因探针评估）；不做 Dify 壳（评估留 V4.3）；不改快慢路判定逻辑。

**✓ 退出门禁**：① V3 八场景断言在包化代码上全绿（行为等价）；② 200 条构造 log 端到端跑通：压缩比 ≥5×、冲突精确检出+零误报、三类失真拦截；③ 误晋升率 0（构造 3 个陷阱集群全部被拦）；④ MCP 5 工具经 Trae 实调成功；⑤ 越权场景：外壳传错身份 → 工具内权限注入拒绝。

## 五、V4.3 全场景 + 运维

**✅ 做什么**
- 报告场景：spec YAML + renderer 注册表 + 叙事层 + 三重闸 + AI 显著标识（V2 场景 B 迁入）。
- 监控归因场景：规则检测 + 归因下钻图 + 告警通道 + "待人工确认"状态纪律（V2 场景 C 迁入）。
- 回测场景：多策略对比 + 口径与生产可复现比对（V2 run_backtest 迁入）。
- 评测扩容：黄金集 20 → 50 题（含 20 对抗口径题，借 WrenAI golden eval 思路）；归因手册 + judge-prompt 落地。
- 运维体系：ops-runbook 告警阈值实战校准；experiments/ 开篇。
- （可选评估）deepagents 子 agent 并行归因探针 PoC；Dify 业务壳评估。

**❌ 不做什么**：不做前端；不做多主题域；不沉淀归因/回测 SQL 为指标。

**✓ 退出门禁**：① 四场景端到端验收（spec.md 3.1 功能全集）；② 黄金集 50 题 ≥95%；③ 归因收敛率有基线（≥70% 三轮内定位）；④ 回测口径与生产复现比对通过；⑤ 运维手册每条告警有一次真实演练记录。

## 六、版本依赖关系

```
V4.0（地基） → V4.1（问数） → V4.2（运营+MCP） → V4.3（全场景）
                              └─ MCP 化可在 V4.1 API 冻结后并行启动（外壳联调依赖 V4.1 的 API 契约）
```

> 并行说明（C0 单开发，仅"自己与自己的轨道"）：MCP 工具的 schema 设计可在 V4.1 批 2 冻结后先行，实现等 V4.1 引擎就绪。
