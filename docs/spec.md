# 需求规格（spec.md）

> 上游：`docs/constraints.md`。本文件是 `releases.md` / `tasks.md` / `evals/` 的需求来源。

## 一、这个项目是什么

**风控问数系统**是一个语义层驱动的指标问数引擎：把风控指标口径（口径宪法）固化成签字的语义层 YAML，分析师用自然语言问指标，系统走"已签字口径"由纯 Python 计算返回数字（LLM 只做意图翻译与叙事，禁止碰数字）；慢路（未命中语义层）的查询日志经"签名归并 → 热度提名 → Owner 签字"沉淀为新口径，实现持续运营。

**明确不做什么**（握手验收探针，最重要的一节）：
1. **不做自研前端**（使用者未到触发条件；入口是 Trae / Chat2DB / CLI / API）；
2. **不做临时快路**（未晋升的查询一律走慢路，系统里不存在"未评审口径在流通"）；
3. **不让 LLM 计算或编造任何数字**（叙事层只许引用 `{{fact_id}}`）；
4. **不接外部客户、不上公网**（内网单机）；
5. **不做归因/回测的 SQL 沉淀**（归因沉淀的是判断框架，回测配置显式建设——V4.3 范围外）；
6. **不做多租户**（单一公司内网使用）。

## 三、验收标准

### 3.1 功能验收（按 releases.md 分版本，此处列全集）

| 域 | 验收项 |
|---|---|
| 问数 | 快路：命中语义层（含 alias）→ enum 收窄 → 纯函数计算 → fact_id + 口径返回；慢路：固定图（schema 链接→生成→执行→修正）+ 强制人审 |
| 纪律 | 三重校验闸（裸数字 / 编造引用 / Python 独立重算）全部生效；未登记指标、未签字指标、未注册纯函数指标均拒服 |
| 人审 | 免审/抽检/必审三级；SLA 72h → 2× 升级 → 7× 组织搁置（shelved ≠ rejected） |
| 持续运营 | 意图签名归并、热度三维度、口径指纹（聚合+WHERE）、晋升（快照+alias+纯函数）、治理三层配置 + 护栏 |
| 接口 | REST API v1（8 端点）+ MCP Server（5 工具）；行级权限在工具内注入 |
| 场景 | 问数 / 报告 / 监控归因 / 策略回测四个编排，各自独立 workflow |

### 3.3 边界验收

- 越权访问：行级权限注入后，任何外壳/API 调用拿不到越权数据（安全测试清单全过）。
- 数据边界：全链路（含 LLM 网关）无任何指标数据外传出内网（默认本地模型）。
- 空报告拒绝：无事实禁出报告（`finish` 前闸拦截）。

### 3.4 性能验收

| 场景 | 目标 | 说明 |
|---|---|---|
| 快路单次问数 | P95 < 2s | 文件快照 + 纯函数（本地 LLM 意图翻译 < 500ms） |
| 慢路单次探查 | < 60s | 含 LLM 生成 + 执行 + 最多 2 轮修正 |
| 报告生成（10 指标） | < 5min | 固定 DAG，无重试风暴 |
| 签名归并（10 万条 log） | < 5min | 代码聚类，非 LLM |

### 3.5 安全验收

见 `docs/security.md` 安全测试清单（SQL 注入三道闸、提示注入隔离、越权 0 通过、审计完整、密钥零泄露）。

## 四、本期不做（V4.3 之后才评估）

1. 自研 Web 前端（触发条件：使用者 > 10 人且非技术背景占多数 / 需审批流配置 / 对外交付）；
2. 归因分析、策略回测的查询沉淀为语义层指标（只做指标问数运营化，V3 已确认边界）；
3. PostgreSQL / 向量检索 / pgvector（并发写或检索需求出现再升，见 ADR-0003）；
4. 多主题域扩展（本期单主题域：贷中风险，10—20 指标起步）；
5. K8s / 容器编排（单机部署，见 ADR 与 ops-runbook）。

## 五、业务流程与规则（只有用户能填的核心规则）

### 5.1 问数主流程（快路）

```
分析师提问 → 同义词/alias 归一 → 命中语义层？
  ├─ 命中 → FC enum 收窄(metric/dims/filters/time_range) → 前闸校验
  │        → 纯函数计算 → FactStore(fact_id) → 返回数字+口径+证据引用
  └─ 未命中 → 慢路（见 5.3）
```

### 5.2 晋升主流程（持续运营，七环节）

```
慢路执行 → raw log 无条件落库 → LLM 意图抽取(签名=(metric,dims,filters,time_range))
→ 代码归并聚类 → 热度三维度 + 口径指纹冲突检测 → 提名/拦截
→ LLM 生成 Owner 评审材料（按签名分组、只标异类）→ Owner 签字
→ 晋升三件事：写 YAML + evidence 快照固化 + alias 回填（+ 硬纪律：同步注册纯函数）
```

### 5.3 人审规则（三级）

| 级别 | 触发条件 | 动作 |
|---|---|---|
| 免审 | 快路命中 + 已签字指标 + 行级权限内 | 直接返回，记录审计 |
| 抽检 | 慢路 + 低敏维度 + 历史同签名无冲突 | 先返回后抽检（默认 10%） |
| 必审 | 慢路新签名 / 口径冲突候选 / 越权边缘 / 归因结论 | 结果先进待审队列，确认后才可引用 |

### 5.4 数字纪律（最高优先级，见 AGENTS.md P-03/P-06/P-07）

计算层纯 Python；LLM 只做意图翻译、叙事、材料汇编；叙事层禁裸数字；引用必须回表存在。
