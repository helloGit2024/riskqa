# docs/risk-register.md · 风险登记簿

> 本文件的**唯一事实来源**：项目已知的风险、它们的严重度与处置状态。
> 主要输入是 2026-11-01 文档集交付前的**四视角对抗评审**（用户 / 攻击者 / 运维 / 会计），
> 但不限于评审——访谈里的担忧、外部依赖、被推翻的假设，都进这本账。

---

## 一、风险从哪来（四个来源）

| 来源 | 说明 | 谁负责补 |
|---|---|---|
| ① **对抗评审四视角** | 用户 / 攻击者 / 运维 / 会计——主要来源 | AI 跑，用户裁决 |
| ② **访谈中的明确担忧** | 用户自己说"我最怕 XXX" | 访谈轮记录 |
| ③ **外部依赖** | 数仓导出、内网 LLM endpoint、Owner 时间、内网 Git 服务 | 发现即记 |
| ④ **被推翻的假设** | `assumptions.md` 第三节回填 | 复核后补 |

> ⚠️ **风险登记不是"负面清单"，是定价工具。**

## 四、严重度判定（不要凭感觉）

| 严重度 | 判定标准 | 处置要求 |
|---|---|---|
| **HIGH** | 会导致**数据泄露 / 资损 / 上线失败 / 返工重写** | **必须闭合**，或进 `OPEN-QUESTIONS.md` 的阻塞项 |
| **MED** | 会造成返工或延期，但不致命 | 给保守默认值，处置入任务验收 |
| **LOW** | 影响可读性 / 一致性 / 美观 | 当场改掉，不进本台账 |

## 五、四条纪律

1. **四视角零发现 = 重跑，不是通过。** 一个视角找不到问题，几乎总是"没认真跑"；重跑后仍为零，要在本台账写明"具体查了哪几处"。
2. **HIGH 必须闭合后交付。** 允许的例外只有一种：升级为阻塞项——而阻塞项总数**不得超过 3 条**。超过 3 条说明需求本身没谈清楚，**回到访谈，不要硬着头皮开工**。
3. **每条都要有"落在哪"。** 写不出具体位置的发现直接作废——它无法被验证，也无法被关闭。
4. **闭合要有证据。** "已修复"不算闭合；"改了 `api-contract.md` §4.2 并加了硬门禁 QG-08"才算。
