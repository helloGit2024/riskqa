# 评估链路规则（eval）

> 按需加载。冲突时以 `AGENTS.md` P-17 与 `docs/spec.md` 第三节为准。

## 1 · 评估的核心纪律

- **比结果集，不比 SQL / 答案文本**：列序行序无关、列名不参与、数值给容差（默认 1e-4，比率类 1e-6）。
- **题库冻结**：`evals/golden_set.yaml` 定版后只许加题（新版本号），**不许改题**——为了让评估通过而改题 = 自欺（AGENTS 禁止清单）。
- 每跑一次评估记录：题库版本、seed、frozen_now、引擎版本——否则"通过率"不可比。

## 2 · 评估指标分层

| 层 | 指标 | 门槛 |
|---|---|---|
| 路由 | alias 归一准确率（口语 → 标准指标） | ≥ 95% |
| 快路 | 黄金题集通过率（含口径正确性） | ≥ 95% |
| 慢路 | SQL 一次通过率 / 交叉验证一致率 | 有基线即可，趋势上升 |
| 拒答 | 该拒的拒了多少（发明指标/越权/无事实） | 100%（这是纪律不是概率） |
| 治理 | 归一压缩比 / 冲突检出率 / 误报率 / 误晋升率 | ≥5× / 精确 / 0 / 0 |

## 3 · 应拒答怎么评分

拒答类题目（发明指标、乱拆维度、越权请求、要求 LLM 算数）的评分标准只有两种结果：**正确拒绝**（含拒绝原因）或**失败**。部分拒绝、拒绝但返回了数据、拒绝理由编造口径——全部计失败。这类题不设"容差"。

## 4 · LLM-as-Judge 的边界

- judge-prompt.md 只用于**叙事质量**（可读性、结构、口径引用完整性）打分；**数字正确性一律用结果集比对**——不让 LLM 评数字（P-03）。
- 叙事类打分必须抽 ≥10% 人工校准；judge 与人工分歧 >20% 的题目类型，停用 judge 该类。

## 5 · 归因（效果变差怎么查）

完整流程在 `evals/attribution.md`。三条铁律：
1. 先查变更（语义层/配置/模型/快照四类，按时间对齐）再查模型；
2. 对照实验：固定题库 + 只变一个变量；
3. 归因结论必须人工确认后才写进实验记录——自动归因不可靠（V3 同款纪律）。

## 6 · Reject List

- ❌ 改 frozen 题库的题面/期望值来提分
- ❌ 用真模型跑失败场景测试（用 FakeLLM，P-17）
- ❌ 把"比结果集"降级成"比 SQL 文本"或"人工看一眼"
- ❌ 评估通过率单点汇报（必须带题库版本与变更记录）
