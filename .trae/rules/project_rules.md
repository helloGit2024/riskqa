# 项目规则 · 风控问数系统

> 本文件在**每一轮对话前自动注入**，只承载"每轮都必须生效"的硬约束。
> **总长 ≤180 行** —— 超了会挤占任务上下文。详细内容外链到 `docs/`，本文件只放**指针 + 硬规则**。

## 0 · 先记住三件事

1. 本项目有完整前置文档（在 `docs/`），**开工前先读，不要凭想象写代码**。
2. 遵循 `docs/releases.md` 的**当前版本范围**：不在范围内的东西**一律不做**，哪怕它看起来很有用。
3. 规则冲突时：**本项目规则 > 用户级规则 > 你的猜测**。

## 1 · 开工前先读哪个文件（按场景查表，不要全读）

## 2 · 技术栈（锁定，禁止擅自更换）

| 层 | 选型 |
|---|---|
| 语言 | Python 3.13 + pandas/numpy + PyYAML |
| 编排 | LangGraph 1.2.x |
| LLM | 自研网关（OpenAI 兼容），本地模型优先 |
| 数据库 | SQLite（运营）+ 文件快照（指标） |
| API / MCP | FastAPI + 官方 mcp SDK |
| 测试 | pytest + FakeLLM |

> 更换任何一项，**先改 `AGENTS.md` 第二节 + 补一份 `docs/adr/`**，再动手。

## 3 · 目录约定

唯一来源是 `REPO_CONVENTION.md` 第三节。一句话版：`src/riskqa/<层>/` 放代码，`config/*.yaml` 放口径与治理，`data/` 放快照与 ops.db，`legacy/` 是只读存档。**写任何路径前先 `ls`，不凭想象。**

## 4 · 硬规则（编号对应 `AGENTS.md` P-xx，违反后果在括号里）

| # | 规则 | 违反后果 |
|---|---|---|
| R1 | 密钥绝不进代码与版本库，只从环境变量读 | （安全事件） |
| R2 | 指标数据不出内网；LLM 默认本地模型 | （合规事故） |
| R3 | **计算层禁 LLM**：数值只由 `calc/` 纯函数产出 | （数字不可信） |
| R4 | 未登记/未签字指标拒服，不猜不填 | （口径失控） |
| R5 | 叙事层禁裸数字，只许 `{{fid}}` 引用，且引用必须回表存在 | （编造数字流出） |
| R6 | FC/MCP enum 从语义层自动生成，禁止手写 | （新指标隐形） |
| R7 | SQL 三闸 + 行级权限执行前注入；越权返回空结果不报错 | （越权） |
| R8 | 慢路/归因结论过人审，未确认不得标记"已定位" | （未评审结论当事实） |
| R9 | raw log 无条件记录不可变；正式数字基于 manifest 快照 | （不可复现） |
| R10 | 晋升必经 Owner 签字，且同事务完成三件事 | （签字不生效） |
| R11 | 治理配置变更留痕；护栏失败保持旧配置 | （阈值黑箱） |
| R12 | 失败场景用 FakeLLM 测，禁用真模型测失败路径 | （flaky 且烧钱） |
| R13 | renderer 未注册直接抛错，禁止静默跳过 | （报告缺页） |
| R14 | 错误必须显式失败，不许静默吞掉 | （问题延迟暴露） |
| R15 | 改动范围最小化，不许顺手重构无关代码 | （引入新 bug） |
| R16 | 新依赖先申请（改 requirements.txt 要走 AGENTS 技术栈流程） | （供应链风险） |
| R17 | 快路指标必须同步注册纯函数（`promotion.calc_registered=1`），否则快路拒服（P-09） | （能命中不能算） |
| R18 | `config/semantic_view.yaml` 与 `config/governance.yaml` 是口径与参数唯一事实源；代码禁内嵌默认值，DB 不存口径（P-15） | （双事实源） |
| R19 | 所有出口（API/报告/告警）必须带 AI 显著标识与 data_as_of（P-16） | （合规缺陷） |

## 5 · 当前版本范围（**每进入新版本由我更新本节**）

### ✅ 本版本要做（V4.0 底座重构）
- 四个 legacy 单文件迁入 `src/riskqa/` 包结构（行为等价，不改逻辑）
- 语义层/治理 YAML 外置到 `config/`
- SQLite 六表 + store 层
- tests/ pytest 化（V2 九场景 + V3 八场景）
- Makefile + CI 门禁

### ❌ 本版本明确不做
- 不接真 LLM（FakeLLM/规则抽取器）
- 不做 API / MCP（V4.1/V4.2）
- 不加新指标、不改任何计算逻辑
- 不做前端

### 其他版本的范围
`docs/releases.md` 是版本范围的**唯一事实来源**。本文件只写"当前这一版"。

## 6 · 交互协议（我要求的工作方式）

1. **动手前先复述计划**，等我确认再写代码。
2. **一次只推进一个任务**，不要并行改多个不相关的地方。
3. **说完事要交代**：改了哪些文件、对应哪几条验收标准、有没有为了通过而放宽标准。
4. **不确定就问，不要猜**。猜出来的东西要标注"待确认"并加进 `OPEN-QUESTIONS.md`。
5. 回答用中文，简短直接，不要客套。
6. 涉及数字口径的改动，复述时必须引用 `semantic_view.yaml` 里的 owner 与 signed_at。

## 7 · 绝对禁止（Reject List · 永久）

- ❌ 在代码里硬编码密钥 / 连接串 / 客户明细
- ❌ LLM 生成或修改任何一个指标数字（包括"顺手"重算）
- ❌ 把口径逻辑写进任何外壳（Dify/nanobot/Trae 配置）
- ❌ 为了让测试或评估通过而放宽标准、删测试、改评估题
- ❌ 用通用框架的"记忆"替代 evidence 快照
- ❌ 删 raw log / 改已落库的 fact / 无 ADR 换技术栈
- ❌ 在用户级规则与本项目规则冲突时按用户级规则执行
