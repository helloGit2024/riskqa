# 自动评分裁判提示词（evals/judge-prompt.md）

> 版本：v1.0（2026-11-01 首版，改提示词必须升版本号并记录改了什么）
> **纪律：裁判模型不能和被评模型是同一个。**
> 适用范围：**只评叙事质量类**（V4.3 报告场景起）。数字类走规则硬指标、拒答类人工终判——
> 这是本项目与通用模板的差异，理由见 `attribution.md` §八。

## 一、裁判提示词本体（system prompt）

```
你是一个严格但公正的评审。你的任务是评价一个风控问数系统的答案是否合格。

你会收到五段信息：
1. 【问题】用户的问题
2. 【口径卡】该问题的指标口径（desc/owner/signed_at/changelog，来自语义层 YAML）
3. 【证据】回答时唯一被允许使用的数字证据（FactStore 的 fact_id → 数值表）
4. 【待评答案】需要你评价的答案
5. 【参考要点】人工整理的关键点（可能不完整）

你要评四个维度，每个 0—1：
1. 忠实度：答案里的每一句话是否都能在【口径卡】或【证据】里找到依据？有编造 → 该维度接近 0。
2. 相关性：答案是否直接回答了【问题】？答非所问 → 0。
3. 完备性：对照【参考要点】，该说的信息有没有遗漏？
4. 数字精确性：答案中的数字是否与【证据】完全一致（逐个比对，容差 1e-6）？改动或自行计算 → 0。

【拒答题的特殊处理】
如果【问题】的答案根本不在【口径卡】与【证据】里：
- 答案明确拒答（如"该指标未登记/无该时段数据，无法计算"）→ 四个维度都给 1。
- 答案编了一个内容 → 全部给 0。

【一票否决项（任一出现，verdict 直接 fail）】
- 答案包含【证据】里不存在的数字；
- 答案把未登记指标当成已登记指标回答；
- 答案给出预测值、行业均值等口径外判断。

输出格式（严格遵守，必须是合法 JSON）：
{ "faithfulness": 0.0, "relevancy": 0.0, "completeness": 0.0, "numeric": 0.0,
  "verdict": "pass|fail", "reason": "一句话说明扣分原因" }
```

## 二、为什么这个提示词要这样写（逐条解释）

| 写法 | 为什么 |
|---|---|
| 明确列出"你会收到五段信息" | 防止模型自己去猜输入格式 |
| 数字精确性单独成为一个维度 | 数字错误比措辞问题严重得多，不能混在"忠实度"里 |
| **拒答题单独处理** | 不加这一段，模型会把"老实说不知道"判成低分——正好鼓励了编造 |
| 一票否决项显式列出 | 本项目数字纪律（P-03/P-06/P-07）没有"部分正确"，编造即失败 |
| 要求输出必须是合法 JSON | 否则没法自动统计 |
| "reason 一句话" | 限制长度，防止它写一堆废话把 token 花光 |

## 三、人工校准方法（每轮评估必做）

抽 **10—20 条**人工评一遍，和裁判结果对比：

| 情况 | 说明 | 处置 |
|---|---|---|
| 一致 | 正常 | 继续 |
| 裁判给高分、人工给低分 | **危险**（放过了错误答案） | 收紧裁判标准 |
| 裁判给低分、人工给高分 | 浪费（冤枉了好答案） | 放宽 |

> 一致率低于 **80%** 时，**裁判的分数不能用**——先修提示词或换裁判模型，再评估。

## 四、哪些题必须走人工评分（不交给裁判）

- **所有数字类**（裁判对数字不敏感；且本项目 ground truth 可由纯函数复算，机器比人可靠）
- **所有拒答类**（这是最容易被判错的一类；runner 机器预筛 + 人工终判）
- 口径声明类（Q011—Q014，口径对错是事实问题不是偏好问题，用 must_contain 规则判）
- 主观质量类（例："这个解释好不好懂"）——人工

## 五、成本控制

| 做法 | 效果 |
|---|---|
| 只对 "判定结果不确定" 的题调裁判 | 省 60% 以上 |
| 先跑规则类硬指标（结果集/禁列比对），只把剩下的交裁判 | 数字类零成本 |
| 每轮评估不要全量重跑，只跑受影响的部分 | 省大头 |
| 评估主力用 FakeLLM 脚本（P-17） | 零 token；真模型只做校准抽检 |
